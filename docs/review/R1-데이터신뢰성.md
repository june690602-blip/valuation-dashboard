## 이 라운드가 답할 질문

> **이 값이 정말 우리가 생각하는 그 값인가?**

계산이 옳은지, 가정이 타당한지, 문장이 좋은지는 **보지 않는다.** 그건 R2·R3의 일이다.
여기서는 오직 **수집한 숫자가 이름표와 일치하는가**만 본다.

## 왜 이게 첫 라운드인가

이 저장소에 이미 두 건의 전례가 있다. 둘 다 데이터를 잘못 골라 **체계적 편향**이 생긴 경우다.

- `cf78389` (이슈 #35) — 역사적 PER·PBR 밴드가 배당조정 주가를 써서 적정가가 낮게 나왔다.
  KB금융 기준 최대 **26.6%** 왜곡. 방향이 늘 같아서(항상 고평가 쪽) 무작위 오차가 아니었다.
- `a70ca59` — ETF 배당·52주 밴드에 같은 문제. 체계적 고평가 편향.

계산식은 둘 다 맞았다. **입력이 틀렸다.** 이런 건 가정 검토로는 절대 잡히지 않는다.

## 점검 항목

각 항목마다 **"확인함 / 문제 발견 / 확인 불가"** 중 하나로 결론 낸다.

### A. 가격 계열 — 수정종가 vs 실제 거래가

- [ ] `prices`(수정종가)와 `prices_raw`(미조정)를 쓰는 **모든 지점**을 나열했는가
- [ ] **가격이 필요한 계산**(밴드·52주·괴리)에 미조정을 쓰는가
- [ ] **수익률이 필요한 계산**(베타·상대성과·백테스트 수익)에 수정종가를 쓰는가
- [ ] 미조정 데이터가 없을 때의 폴백이 **조용히 편향을 만들지 않는가**

> 이슈 #35에서 고친 4곳(`valuation.py:172`, `ai_analysis.py:281`, `backtest.py:124,158`)
> 외에 **같은 실수가 남아 있는지 전수 확인**하는 것이 이 항목의 핵심이다.

### B. 단위와 통화

- [ ] 한국 재무 단위(원 / 천원 / 백만원 / 억원)가 소스마다 다른데 정규화되는가
- [ ] 미국 종목의 EPS·재무 통화가 표시 통화와 일치하는가 (ADR·해외법인 주의)
- [ ] 시가총액·매출처럼 **자릿수가 큰 값**이 화면 포맷터를 거치며 어긋나지 않는가

### C. 시점 정합

- [ ] 주가 시점과 재무 시점이 섞여 계산되지 않는가 (PER = 오늘 주가 ÷ 언제 EPS?)
- [ ] NAV처럼 **지연 공시되는 값**이 당일 시세와 비교돼 가짜 괴리를 만들지 않는가
  (한국 ETF는 공시 괴리율을 우선 쓰도록 이미 처리됨 — `etf.py:_premium` 참고)
- [ ] TTM 계산의 롤링 창이 결산월이 다른 종목에서도 맞는가

### D. 소급·생존 편향

- [ ] 피어 목록이 **현재** 구성인데 과거 계산에 쓰이는 곳이 있는가
- [ ] 백테스트가 그 시점까지의 데이터만 쓰는가 (룩어헤드)
- [ ] 상장폐지 종목이 빠진 목록으로 과거를 평가하는 곳이 있는가

### E. 결측 처리

- [ ] 값이 없을 때 `None`으로 남는가, 아니면 **0이나 기본값으로 조용히 대체**되는가
  (0 대체는 계산을 통과시키면서 결과를 왜곡하므로 가장 위험하다)
- [ ] 파싱 실패가 예외로 드러나는가, 조용히 빈 값이 되는가

## 검증 방법

**대화로 값을 주고받지 말고 스크립트를 만든다.** 재현 가능성이 근거의 핵심이고,
스크립트 자체가 산출물이 된다. 기존 `scripts/check_*.py` 패턴을 따른다.

제안: `scripts/check_data_integrity.py` — 대표 종목 몇 개(고배당/저배당, 한국/미국,
금융/제조)에 대해 위 A~E를 자동 점검하고 표로 출력한다.

대조 대상은 **무료로 확인 가능한 외부 원본**이다 — 네이버금융 화면값, DART 공시 원문,
거래소 공시 괴리율 등.
