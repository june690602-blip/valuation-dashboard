## 이 라운드가 답할 질문

> **이 값이 정말 우리가 생각하는 그 값인가?**

계산이 옳은지, 가정이 타당한지, 문장이 좋은지는 **보지 않았다.** 그건 R2·R3의 일이다.
여기서는 오직 **수집한 숫자가 이름표와 일치하는가**만 봤다.

## 어떻게 확인했나

발견을 대화로 주고받지 않고 `scripts/check_data_integrity.py` 하나로 모았다. 두 부분이다.

**① 정적 검사 (네트워크 불필요)** — 가격 계열을 읽는 `src/` 안의 모든 함수를 AST로 뽑아
두 레지스트리에 대조한다.

- `PRICE_LEVEL_SITES` — '그날 붙어 있던 가격'이 필요해 **미조정**을 써야 하는 곳
- `TOTAL_RETURN_SITES` — 수익률 기준이라 **수정종가**가 맞는 곳

어느 쪽에도 없는 함수는 `[문제] 미분류`로 떨어진다. 이슈 #35 같은 실수가 **다시 들어오면
검사가 깨지도록** 만든 회귀 방어선이다. 앞으로 가격 계열을 읽는 함수를 추가하면 레지스트리에
등록해야 통과한다.

**② 라이브 검사** — 대표 종목 패널에 A~E를 돌린다.
한국·금융·고배당(KB금융) / 한국·제조·저배당(삼성전자) / 미국·제조·고배당(코카콜라) /
미국·기술·저배당(애플) / **ADR(TSMC)** 다섯이다. ADR을 넣은 건 재무 통화와 표시 통화가
갈리는 유일한 축이기 때문이고, 실제로 여기서 가장 큰 왜곡이 나왔다.

```bash
python scripts/check_data_integrity.py            # 정적 + 대표 종목 패널
python scripts/check_data_integrity.py --static   # 정적만 (키·네트워크 불필요)
python scripts/check_data_integrity.py KR 005930  # 종목 하나
```

각 점검은 **확인 / 문제 / 불가**로 결론 낸다. '불가'는 실패가 아니라 **무료 데이터로는 대조할
원본이 없다**는 결론이고, 그대로 3번 바구니가 된다.

## 점검 항목 결과

### A. 가격 계열 — 수정종가 vs 실제 거래가

- [x] `prices`(수정종가)와 `prices_raw`(미조정)를 쓰는 **모든 지점**을 나열했는가
      → 정적 검사가 `src/` 전체를 훑는다. 등록 지점 25곳, 미분류 0곳.
- [x] **가격이 필요한 계산**(밴드·52주·괴리)에 미조정을 쓰는가 → **3곳이 아직 아니다** (발견 1·5)
- [x] **수익률이 필요한 계산**(베타·상대성과·백테스트 수익)에 수정종가를 쓰는가 → 전부 맞다
- [x] 미조정이 없을 때의 폴백이 조용히 편향을 만들지 않는가
      → `actual_prices()`가 `prices`로 폴백하고 provider가 경고를 남긴다. 조용하지 않다.

이슈 #35에서 고친 4곳(`valuation.py:172`, `ai_analysis.py:281`, `backtest.py:124,158`)은
**여전히 미조정을 읽는다**. 회귀 없음. 다만 **고쳐지지 않고 남은 곳**이 3곳 있었다(발견 1·5).

배당 조정이 만드는 왜곡의 크기를 5년 전 시점에서 실측했다 —
KB금융 **-21.0%**, 삼성전자 -9.4%, 코카콜라 -13.7%, TSMC -7.8%, 애플 -2.5%.
고배당일수록 크고 **방향이 항상 같다**(과거를 낮춰 잡음). 무작위 오차가 아니라 체계적 편향이라는
#35의 진단이 이번에도 그대로 재현됐다.

### B. 단위와 통화

- [x] 한국 재무 단위 정규화 → 원 단위로 일관. 공시 시총 대조 KB금융 -1.15%, 삼성전자 +0.46%

      KB금융 -8.0% · 삼성전자 -12.8% · 코카콜라 -0.1% · 애플 +0.2%

- [x] TTM 롤링 창이 결산월이 다른 종목에서도 맞는가 → **확인 불가**(한계 4). 애플(9월 결산)이 해당

### D. 소급·생존 편향

- [x] 피어 목록이 현재 구성인데 과거 계산에 쓰이는가 → **지금은 아니다**(한계 2)
- [x] 백테스트가 그 시점까지의 데이터만 쓰는가

- [x] 상장폐지 종목이 빠진 목록으로 과거를 평가하는가 → 해당 계산 없음

### E. 결측 처리

- [x] 값이 없을 때 `None`으로 남는가, **0으로 조용히 대체**되는가
      → **전 종목에서 0 대체 0건.** 결측은 전부 `NaN`으로 남는다. 가장 위험한 항목이 깨끗하다.
- [x] 파싱 실패가 조용히 빈 값이 되는가
      → `naver.py:_parse_number`는 실패 시 `None`, provider가 경고를 남기고 계산값으로 폴백.

발견 3에서 **처음 판단이 틀렸다.** 조서에는 '지금 고침'으로 적었지만, 파고 보니 환율만의
문제가 아니었다 — 재무제표의 주식수는 보통주(~25.9억), `info`의 주식수는 ADR 증서
(51.9억) 기준이라 **주당 단위까지 어긋나** 있었고, ADR 비율은 무료 소스가 주지 않는다.
그래서 이번엔 차단만 하고 변환은 #56으로 넘겼다. 야후가 직접 주는 값도 이미 틀려 있어

수정 과정에서 조서의 가설 하나가 더 기각됐다 — `ifrs-full_FinanceCosts`('금융비용')를

### 이 보증이 미치지 않는 범위

감사에서 중요한 건 무엇을 확인했는지만큼 **무엇까지만 확인했는지**다.

- **표본 5종목이다.** 전 종목이 아니다. 이 다섯이 축을 갈라 고른 것이긴 하나,
  코스닥 소형주·적자 기업·리츠처럼 결측 양상이 다른 부류는 보지 않았다.
- **2026-07-28 한 시점이다.** 무료 데이터는 제공처 사정으로 스키마가 바뀐다.
  실제로 야후가 배당수익률 단위를 바꿨던 전례가 있고, 그래서 #58을 남겼다.
- **증거의 절반 이상이 내부 정합이다.** 외부 원본과 맞춰본 건 공시 시가총액·공시 PER·
  DART 대 yfinance 세 갈래뿐이다. 내부 정합은 '앞뒤가 맞는다'는 말이지 '맞다'는 말이 아니다.
  둘이 같은 방향으로 함께 틀리면 잡히지 않는다.
- **정적 검사는 등록된 지점만 본다.** 새 함수가 레지스트리에 안 들어가면 `[문제] 미분류`로
  떨어지므로 누락은 드러나지만, 레지스트리의 분류 자체가 틀렸다면 그건 못 잡는다.
- **3번 바구니(한계) 5건은 그대로 남아 있다.** 재무 빈티지·과거 상장목록·미국 ETF NAV·
  공시 PER 산출식·비12월 결산 TTM — 무료 데이터로는 대조할 원본이 없다.

## 결론

`src/data/`의 값 대부분은 이름표와 일치한다. 특히 **가장 위험한 결측 처리(0으로 조용히 대체)는
전 종목에서 0건**이었고, 이슈 #35에서 고친 4곳도 회귀 없이 미조정 주가를 유지하고 있었다.

그러나 **#35와 같은 종류의 실수가 다섯 군데 더 남아 있었다.** 다섯 다 계산식이 아니라 입력이
틀렸고, 다섯 다 방향이 일정한 체계적 편향이다 — 52주 밴드가 수정종가로 계산되고(1),
두 가격 계열의 캐시 주기가 달라 같은 날짜에 두 개의 가격이 생기고(2), ADR의 재무 통화를
확인하지 않아 PER이 환율배만큼 틀리고(3), DART 매핑이 '이자비용' 자리에 '이자지급'을(4),
'현금+단기금융' 자리에 '현금'만(5) 넣는다. 가장 큰 것은 TSMC의 통화 불일치로, PER이
0.93 대 35.60이 되어 그 종목의 판정 자체가 무의미했다.

**확인하지 못한 것은 대부분 시간축이다.** 과거 시점의 재무 빈티지도, 과거 시점의 상장 목록도
무료로는 없다. 지금 구조에서는 이 둘이 결과에 들어가지 않지만(백테스트는 계단 지연으로,
피어는 현재 횡단면 사용으로 막혀 있다), **피어나 재무를 과거로 되돌리는 계산을 새로 만들면
그 순간 편향이 들어온다.** 한계 1·2는 그때 다시 읽어야 할 항목이다.

**R2(가정의 적합성)로 넘기는 말:** 발견 3·4·5는 R2가 다루는 값의 **입력**이다.
WACC 감도를 따지기 전에 4가 고쳐져야 하고(k_d 0.61%p), EV/EBITDA 가정을 따지기 전에
5가 고쳐져야 한다(EV 5.3%). 적정가 4방법의 가중치를 흔들어 보는 작업은 이 입력들이
정리된 뒤에 해야 의미가 있다. **R2는 이 PR이 머지된 뒤에 시작하는 편이 낫다.**
