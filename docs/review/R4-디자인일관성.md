## 이 라운드가 답할 질문

> **한 사람이 만든 것처럼 보이는가?**

값이 맞는지(R1)·가정이 타당한지(R2)·문장이 정확한지(R3)는 보지 않았다.
**화면의 생김새를 정하는 값**만 봤다 — 색·크기·간격·그림자·반경·브레이크포인트.

R3가 남긴 셋(#68 노트의 화면상 무게 · #69 헤드라인과 해설의 충돌 · #70 죽은 시안 6장)은

## 어떻게 확인했나

디자인은 "눈으로 봐야 안다"는 축이다. 그런데 **눈으로 본 것은 다음 사람에게 전달되지 않는다.**
그래서 두 갈래로 나눴다.

**하나 — 값은 스크립트로 못 박았다.** `scripts/check_design.py`.

```bash
python scripts/check_design.py          # 전체 (네트워크·키 불필요)
python scripts/check_design.py --list   # 레지스트리(공용 셸·판정 색·대비)만
```

여덟 검사다. A~G는 규약 위반을 찾고, H는 접근성 최소 장치가 놓였는지 보며,
I는 **정적으로는 판정할 수 없는 것**을 명시적으로 남긴다.

| | 검사 | 무엇을 못 박았나 |
|---|---|---|
| A | 공용 셸 | 헤더·네비·브랜드가 7장에서 각각 어떤 구현·어떤 값인지 **전수 등록** |
| B | 토큰 밖의 값 | 색·그림자·반경을 리터럴로 적은 자리 |
| C | 그림자 위계 | `--shadow-card`가 카드급 전용인가(PR #48) · 화면마다 카드 깊이가 같은가 |
| D | 판정 색 | 한 색이 한 가지를 말하는가 · 두 프런트가 같은 계열인가 |

A의 레지스트리가 R1의 `PRICE_LEVEL_SITES`·R3의 `LAYER_SITES`와 같은 역할이다 —
**새 화면을 만들면 등록해야 통과한다.** 등록된 값과 실제가 어긋나면 `[문제]`로 떨어진다.

**둘 — 자리는 브라우저를 띄워 쟀다.** `python server.py`를 올리고
`getComputedStyle`·`getBoundingClientRect`로 실제 렌더 값을 받았다. 스크린샷 대신 숫자를
받은 이유는 두 가지다 — 이 환경에서 스크린샷이 나오지 않고, 무엇보다 **숫자는 조서에
적히지만 인상은 적히지 않는다.** 잰 것은 헤더 높이·브랜드 위치·글자 크기 분포·요소가
스크롤 컨테이너를 벗어나는지·인라인 스타일 밀도다.

### 0. 먼저: 이 라운드는 왜 다른가

이슈 #53이 못 박아 둔 대로다. **디자인은 취향이 섞여 혼자 정하면 안 된다.**
그래서 아래 1번 바구니는 "지금 고침"이 아니라 **"고칠 것이 확정된 것 + 방향을 물어야 하는 것"**

#### ㉯ 판정 색 — 한 색이 다섯 가지를 말한다

`--dv-positive`(초록) 하나가 주식 화면에서 **다섯 가지**를 말한다.

1. 저평가 **판정** (`stock.js:893,918`)
2. 일간 등락·초과수익 (`:347,355`)
3. 백테스트 수익률·순위상관 부호 (`:1348,1355,1718`)
4. 해설의 good/bad 아이콘 (`:973`)
5. 피어 대비 싸다/비싸다 (`:1096`)

**초록을 본 사람은 그게 "싸다"인지 "올랐다"인지 색만으로 갈라낼 수 없다.**
게다가 이 둘은 자주 반대 방향이다 — 주가가 오르면 저평가 폭은 줄어든다.

더 큰 것은 **두 프런트가 다른 계열을 쓴다**는 것이다.

| 프런트 | 저평가 | 고평가 |
|---|---|---|
| Streamlit (`components.py:VERDICT_COLORS`) | `#2a78d6` 파랑 | `#e34948` 빨강 |
| Meridian 웹 (`stock.js:893`) | `--dv-positive` 초록 | `--dv-negative` 클레이 |

CLAUDE.md는 「**파랑=저평가·빨강=고평가는 판정 전용**」이라고 적었다. 규칙을 지키는 쪽은
Streamlit이고, 실제 실행 진입점(`대시보드실행.bat` → Meridian 웹)은 지키지 않는다.
**규칙 문서와 주력 화면이 다르다.**

덤으로 판정 눈금 양끝의 가독 등급이 갈린다 — 저평가 `--dv-positive` 4.75:1(AA 통과),
고평가 `--dv-negative` 4.12:1(AA 미달). R3 발견 2가 "한 눈금의 양끝은 같은 계열로 부른다"고
했던 것의 색 판본이다.

> **물어야 할 것**: **판정에 어떤 색을 줄까?**
> ① CLAUDE.md대로 파랑/빨강을 판정 전용으로 되찾고, 등락·수익률은 초록/클레이에 남긴다
>   — 규칙과 화면이 일치. 다만 웜톤 지면에 빨강이 얹히고, 파랑은 이미 `--dv-navy`가 링크·차트 주선에 쓴다
> ② 판정만 **채도를 뺀 잉크 계열**(진하기 차이)로 바꾸고 색은 등락에만 남긴다
>   — "판단은 단정하지 않는다"는 프로젝트 톤과 맞는다. 대신 판정이 눈에 덜 띈다
> ③ 판정은 초록/클레이를 유지하고 **등락·수익률을 다른 계열로** 옮긴다
>   — 지금 화면의 인상을 지킨다. 대신 CLAUDE.md의 규칙 문장을 고쳐야 한다

> ② 텍스트로 쓰는 토큰만 올리고, 장식(테두리·구분선)으로 쓰는 값은 그대로 둔다
>   — `--ink-3`을 텍스트용/장식용 둘로 가른다. 손이 가장 많이 가지만 톤을 지킨다
> ③ `--warning`과 `--dv-negative`만 먼저 올린다(경고와 판정) — 최소 변경, 나머지는 한계로 남긴다

#### ㉱ 카드 깊이 — 화면마다 다르다

`--shadow-card`가 **카드급 컨테이너 전용**이라는 PR #48의 규약 자체는 지켜지고 있다(11곳 전부 카드급).
문제는 **그 카드를 어떤 화면이 쓰느냐**다.

- 뜬 카드: `stock.html`(3) · `guide.html`(4) · `test.html`(4)
- 평평한 화면: `home.html` · `bond.html` · `portfolio.html` · `admin.html`

홈은 `--shadow-sm/md/lg`로 자기 위계를 따로 만들었고(`.ent.lead`=lg, `.ent.sub`=sm),
금리·포트폴리오는 그림자가 **하나도 없다**. 같은 "테두리 있는 상자"가 화면에 따라
떠 있기도 하고 지면에 붙어 있기도 하다.

> **물어야 할 것**: 홈의 3단 위계(lead/sub/strip)를 **전 화면 공용 규약으로 올릴까**,
> 아니면 홈만의 예외로 못 박고 나머지는 `--shadow-card` 한 단계로 갈까?

## 결론

**이 대시보드의 디자인 시스템은 잘 설계돼 있고, 잘 배포되지 않았다.**

`meridian.css`는 205줄짜리 작은 파일인데 그 안에 있는 결정은 정확하다 — 지면은 미색 종이,
색은 데이터에만, 그림자는 절제, 반경은 거의 직각. 주석은 그 이유까지 적어 두었다.
PR #48이 못 박은 `--shadow-card` 규약은 11곳 전부에서 지켜지고 있고, 접근성 최소 장치
(포커스 링·모션 축소·`aria-*`·표 스크롤)도 놓여 있다.

**문제는 전부 "그 결정이 닿지 않은 곳"에 있다.** 그리고 원인은 세 가지다.

- **토큰이 없는 축이 둘이다**(㉳). 타이포 크기와 간격은 애초에 토큰이 없어서, 각 화면이
  자기 값을 정할 수밖에 없었다. 글자 크기 27가지·`gap` 24가지는 누가 게을러서 생긴 게
  아니라 **기댈 눈금이 없어서** 생겼다. 브레이크포인트 12가지도 같은 이유다(㉲).
- **한 색이 여러 뜻을 진다**(㉯). `--dv-positive`가 판정이면서 등락이면서 수익률이다.
  R3가 어휘에서 "적정가를 계산한 자리에서만 판정 어휘를 쓴다"고 층위를 갈랐는데,
  **색에는 그 층위가 없다.** 그리고 CLAUDE.md의 색 규칙은 Streamlit만 지키고 있어서,
  주력 화면과 규칙 문서가 다른 말을 한다.
- **개선이 한 화면에서 멈춘다**(㉮). 홈 리디자인(B4)은 좋은 셸을 만들었지만 홈에만 남았다.
  R3가 "PR #47의 원칙이 그 PR이 손댄 자리에만 적용됐다"고 쓴 것과 **같은 모양이다.**
  다른 점은 화면 언어는 스크립트로 못 박을 수 있었고, 셸은 **파일을 합쳐야 끝난다**는 것이다.

**가장 큰 것은 ㉮다.** 홈에서 주식으로 넘어가는 한 번의 클릭에서 로고가 사라지고, 헤더가
낮아지고, 지면이 미색에서 순백으로 바뀐다. "한 사람이 만든 것처럼 보이는가"라는 이 라운드의
질문에 화면이 직접 답하는 지점이다. 그 다음이 ㉯(색이 다섯 가지를 말한다)이고,
㉰(경고가 가장 안 읽힌다)는 크기는 작지만 **R2·R3가 공들여 올린 문장을 무력화한다**는
점에서 무겁다.

**확인하지 못한 것은 취향이다.** R1의 벽은 시간축, R2는 관측창, R3는 독자였다.
R4의 벽은 "어울리는가"이고, 이건 계산되지 않는다. 그래서 이 조서는 **발견까지만 확정하고
방향은 열어 두었다** — 이슈 #53이 이 라운드만 진행 방식을 다르게 정한 이유다.
