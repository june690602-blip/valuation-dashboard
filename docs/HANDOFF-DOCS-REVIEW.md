## 1. 신뢰도 배지를 뗀다 ★ 먼저 한다

### 왜 — 재봤더니 **말과 실제가 반대**였다

KR 패널 7,656행에 현행 `confidence_grade`를 그대로 적용해 잰 값이다.

**㉠ 3단인데 2단이다.** `높음`이 **0건**이다.

| 등급 | 건수 | 비율 |
|---|---|---|
| 높음 | **0** | 0% |
| 중간 | 3,887 | 50.8% |
| 낮음 | 3,769 | 49.2% |

코드 주석이 이미 알고 있었다 — `warranted.py`의 `NEFF_FRAC_*` 위에
*"'높음'은 여전히 사실상 도달 불가다(실측 KR 0%)"*라고 적혀 있다.

**㉡ 그리고 방향이 뒤집혀 있다.** *"덜 믿으세요"*라고 붙인 판정이 **더 잘 맞는다.**

| 자 | 낮음 IC | 중간 IC | 낮음 간격 | 중간 간격 |
|---|---|---|---|---|
| 1년 | **0.109** | 0.090 | **14.8%** | 8.6% |
| 3년 | **0.148** | 0.147 | **26.1%** | 22.7% |
| 5년 | **0.196** | 0.185 | **48.1%** | 37.7% |

세 자 모두, 두 지표 모두 같은 방향이다.

**기제 짐작** — 지금 신뢰도는 사실상 *"방법들이 서로 얼마나 비슷한 값을 냈나"*다.
방법이 딱 붙어 있으면 괴리율이 0 근처라 **할 말이 없는 종목**이고, 갈리면 괴리율이 큰
종목이다. 즉 *"믿을 만함"*이 아니라 *"할 말이 있음"*을 재고 있었다.

> ⚠ **연관만 봤지 원인은 못 밝혔다.** 낮음 집단이 더 작고 변동성 큰 종목이라면 무엇을
> 재도 더 벌어진다. **이 인계문은 "배지가 예측을 뒤집는다"를 증명하지 않는다** —
> 증명한 것은 **"배지가 주장하는 것을 하지 못한다"**까지다. 떼는 근거로는 그것으로 충분하고,
> 새 지표를 만들려면 별도 사전등록이 필요하다(아래 §3).

### 재현

```bash
# 위 표를 다시 내는 스크립트는 아직 저장소에 없다 — 만들면서 커밋할 것.
# 재료는 다 있다: 패널의 축 3열(로그 괴리율) + check_backtest_horizon.build()
#   dispersion = std(exp(l))/|mean(exp(l))|   ← valuation.py와 같은 식(ddof=0)
#   n_eff      = warranted.effective_axes(methods, "KR")
#   등급        = valuation.confidence_grade(disp, n, n_eff, capped)
```

**스크립트로 만들어 커밋해라.** 이 인계문의 표만 남기고 재현 수단이 없으면, 다음 사람이
이 숫자를 못 믿는다 — 오늘 인계문의 `10.9%/15.3%`가 정확히 그래서 문제가 됐다
([ADR-0041](adr/0041-weight-width-is-measured-per-stock.md) §재현 실패).

### 어디를 건드려야 하나

**떼는 것은 화면이고, 계산은 남겨도 된다.** `dispersion`은 `근거 보기` 안에서
*"방법 간 편차 ±N%"*로 쓸 자리가 있다 — 배지(등급 이름)만 없애는 것이 최소 변경이다.

| 파일 | 무엇 |
|---|---|
| `web/assets/stock.js:1047` | **헤더의 `신뢰도 [등급]` 배지** — 이것이 본체다 |
| `web/assets/stock.js:868` | `confTip` — 산출 근거 툴팁 |
| `web/assets/stock.js:902` | *"…신뢰도를 '중간'으로 내렸습니다"* 문장 |
| `web/assets/stock.js:1732` | 08 종합 평가 탭의 *"신뢰도 X — 방법 간 편차가…"* |
| `src/analysis/valuation.py` | `confidence_grade` · `res.confidence` · `confidence_spread` · `confidence_cap` · `n_eff` |
| `src/web/serialize.py` | `confidence` · `confidence_spread` · `confidence_cap` · `n_eff` |
| `src/ui/pages/stock.py` · `components.py` | 스트림릿 쪽(아래 §2 ㉢을 먼저 읽을 것) |
| `web/guide.html` · `src/ui/pages/guide.py` | 가이드 설명 |

**ETF는 건드리지 마라** — `stock.js:1789`의 `confTip`은 ETF 전용이고 산식이 다르다
(*"주 신호의 데이터 충실도와 유형 적합성"*). 이번 측정과 무관하다.

### ADR을 써라 — 0022와 0036을 대체한다

[ADR-0022](adr/0022-confidence-counts-effective-axes.md)(실질 축 수)와
[ADR-0036](adr/0036-confidence-cap-measured-as-independence-fraction.md)(독립분 상한)이
이 배지를 만든 문서다. **채택된 ADR은 고치지 않는다** — 새 ADR로 대체 표시한다.
다음 번호는 **0043**이다(0042까지 main에 있다).

ADR에 반드시 넣을 것: **위 ⚠ 절**(연관만 봤다) · **높음 0건** · 세 자 표.

### ㉢ ⚠ 화면이 둘이다 — 이걸 먼저 정해라

이 저장소에는 UI가 **둘** 있다.

```
server.py  → web/         지금 배포된 것 (valuation-dashboard.com)
app.py     → src/ui/      스트림릿. .claude/launch.json의 "dashboard" 설정
```

**사용설명서는 스트림릿 쪽을 설명하고 있다**(사이드바 슬라이더·탭 6개). 배포된 웹은
탭이 다르다 — `01 기업·뉴스 / 02 요약·판정 / 03 주가차트 / 04 밸류에이션 / 05 재무 분석 /
06 업종 비교 / 07 자본비용 / 08 종합 평가`.

**문서를 고치기 전에 스트림릿을 어떻게 할지 정해야 한다.** 셋 중 하나다:

1. **스트림릿을 접는다** — 문서가 한 벌이 된다. 대신 `src/ui/` 전체가 죽은 코드가 되고,
   신뢰도 제거(§1)도 그쪽은 손댈 필요가 없어진다.
2. **둘 다 유지한다** — 사용설명서를 둘로 가르거나, 웹 기준으로 다시 쓰고 스트림릿은 뺀다.
3. **지금은 안 정한다** — 문서에 *"이 설명은 스트림릿 화면 기준"*이라고 못 박아 두기만 한다.

**혼자 정하지 말고 물어라.** 스트림릿을 접는 것은 되돌리기 어렵고, 취업 포트폴리오에서
"두 가지 UI를 만들었다"가 자산일 수도 부채일 수도 있다.

> 확인 안 된 것 하나 — `web/stock.html`에 `data-tab="backtest"`가 **아직 있다.**
> ADR-0009가 탭을 접었는데 남아 있는 건지, 조건부로 숨겨지는 건지 **확인하지 못했다.**
> 문서에 백테스트 탭을 적을지 말지가 여기 걸린다.

### ㉣ 오늘 새로 생겨서 **문서에 아예 없는 것**

- **가중치 폭**(ADR-0041) — `근거 보기` 안에 종목별 범위가 뜬다. 설명이 없다.
- **판정 3등급**(ADR-0042) — 위 표.
- **계수 파이프라인**(이슈 #131) — 밤마다 CI가 계수를 구워 `data-coefficients` 브랜치에
  둔다. README의 아키텍처 절에 한 줄 값어치가 있다.

## 3. 하지 말 것

- **신뢰도를 대체할 새 지표를 즉석에서 만들지 마라.** 그것은 결과를 보고 기준을 만드는
  일이고, 이 저장소가 [ADR-0024]·[ADR-0039]에서 두 번 이해충돌 절을 달아야 했던 그 일이다.
  하려면 **사전등록부터** — 형식은 [`docs/review/2026-08-12-문턱-사전등록.md`](review/2026-08-12-문턱-사전등록.md)를 그대로 베껴라.
- **가중치 숫자를 건드리지 마라**(ADR-0003).
- **문서에 화면보다 강한 말을 쓰지 마라.** 백테스트 결론은 *"한국 2017~2025에서 확인됐고
  미국에서는 확인되지 않았다"*가 상한이다([ADR-0030](adr/0030-us-does-not-replicate.md)).

## 4. 함정

| | |
|---|---|
| **`.venv`는 메인 트리에만** | 워크트리에서는 절대경로로 부른다: `.venv/Scripts/python.exe` |
| **`check_all.py`를 전체로 돌려라** | 한 관문의 통과는 다른 관문에 대해 아무 말도 하지 않는다. 화면 문구를 고치면 `check_screen_language.py`가 걸린다 |
| **인라인 스타일 예산** | `stock.js`를 건드리면 `check_structure.py`가 본다 |
| **새 ADR 전에 다른 워크트리의 `docs/adr/`를 확인** | `check_adr_index.py`는 브랜치를 가로질러 보지 못한다 |
| **앞선 PR과 같은 파일이면 그 브랜치에서 따라** | `git worktree add .claude/worktrees/<이름> -b <새브랜치> <의존브랜치>` |
| **판정 어휘를 손으로 적지 마라** | 오늘 세 곳이 그래서 조용히 깨졌다. `VERDICTS`에서 유도한다 |
| **문턱 숫자를 JS에 적지 마라** | 눈금이 그래서 옛 문턱을 계속 그렸다([PR #153](https://github.com/june690602-blip/valuation-dashboard/pull/153)) |
