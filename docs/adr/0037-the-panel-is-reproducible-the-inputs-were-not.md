# ADR-0037: 패널은 재현된다 — 재현되지 않은 것은 입력이었다 (ADR-0035 정정)

- 상태: 채택됨
- 날짜: 2026-08-10
- 정정 대상: [ADR-0035](0035-drop-historical-band-from-the-verdict.md) §패널은 재현되지 않는다 — **그 절은 틀렸다**
- 재현: `backtest_panel.py`를 두 번 돌리고 두 패널을 비교

## 무엇을 잘못 적었나

ADR-0035는 이렇게 적었다:

> 같은 `raw/`로 패널을 다시 만들었더니 **같은 시점의 종목 집합이 절반도 겹치지 않았다.**
> (…) **이것이 이 ADR보다 큰 문제다.** 지금까지의 백테스트 결론(ADR-0028~0034)이 전부
> "한 번 만든 패널"에 기대고 있는데, 그 패널이 다시 만들면 달라진다면 **그 숫자들의
> 오차가 얼마인지 아무도 모른다.**

**사실이 아니다.** 그 문장은 *"같은 `raw/`로"*를 전제했는데, 그 전제가 성립하지 않았다.

## 실제로 잰 것

같은 코드·같은 `raw/`로 패널을 두 번 만들고 전 열을 대조했다:

```
행수        A 7,656   B 7,656
키 교집합   7,656     · A만 0 · B만 0

열                공통    최대차      다른 값
업종 상대가치      7656   0.00000000        0
수익가치(RIM)     3620   0.00000000        0
정규화 이익        4972   0.00000000        0
역사적 밴드        4883   0.00000000        0
EPV              4945   0.00000000        0
fair_mid         7656   0.00000000        0
price            7656   0.00000000        0
fwd_12m          7601   0.00000000        0

판정이 다른 행: 0
```

**빌더는 결정적이다.** `load_all()`이 `sorted(glob)`으로 전부 읽고, `evaluate()`가
표본을 뽑지 않고 전 종목을 훑는다. 무작위가 들어갈 자리가 없다.

## 그러면 그때 본 차이는 무엇이었나

두 패널이 **입력도 코드도 서로 달랐다.**

| | 8/9 패널 | 8/10 패널 |
|---|---|---|
| `code_commit` | `1f47178` | `066d6d7` 이후 |
| `raw_stocks_at_build` | **1,288** | **1,292** |

`raw/`에 종목 4곳이 늘었다(다른 기기에서 옮겨 온 묶음). 그 사이 판정 코드도 바뀌었다
(ADR-0035가 ②를 뺐다).

**핵심은 이것이다** — `evaluate()`는 매 시점에

```python
coef = build_coefficients(pd.DataFrame(snap))    # ← 그 시점 종목 집합으로 적합
```

회귀 계수를 **그 시점의 횡단면으로 적합**한다. 그리고 ①과 ⑤가 둘 다 그 계수를 쓴다
(⑤ = 8년 평균 이익 × **그 회귀 적정 PER**, ADR-0015). 그래서:

> **표본에 종목이 하나만 더 들어와도 계수가 움직이고, 그러면 ①과 ⑤가 전 종목에서 바뀐다.**

실측이 정확히 그 모양이었다 — `price`와 `fwd_12m`은 공통 행에서 **한 건도 안 달랐는데**
(원자료는 같다) `업종 상대가치`는 **3,628건 전부** 달랐다. 그것을 '재현 실패'로 읽었다.

## 아직 설명하지 못한 것 — 적어 둔다

종목 4곳이 늘어난 것으로 **종목 집합이 시점마다 절반씩 갈리는 것은 설명되지 않는다**
(2016-06-01: old 646 · new 641 · 교집합 336). 두 집합이 같은 풀에서 독립적으로 뽑힌
것처럼 보이는 크기다.

8/9 시점의 `raw/`를 복원할 수 없어 **원인을 확정하지 못했다.** 지금 코드가 결정적인
것은 확인했으므로, 그때의 빌드가 무엇을 달리 했는지는 알 길이 없다.

**모른다고 적는다.** 다음에 같은 일이 생기면 아래 결정으로 답할 수 있다.

## 결정

### 1. 매니페스트가 `raw/`의 **지문**을 적는다

개수(`raw_stocks_at_build`)만으로는 두 패널이 비교 가능한지 알 수 없다. 파일 이름과
크기를 해시해 한 줄로 남긴다:

```json
"raw_fingerprint": "sha256:4e4974876255b6fa (3876파일)"
```

내용 전체를 해시하지 않는 것은 3,876개를 읽어야 해서다. 크기는 값싼 대리 지표다 —
같은 종목의 데이터가 갱신되면 크기도 대개 바뀐다.

### 2. 두 패널을 비교하려면 `code_commit`과 `raw_fingerprint`가 **둘 다** 같아야 한다

매니페스트의 `note`에 적었다. 하나라도 다르면 회귀 표본이 달라 **축 값이 전부 움직인다.**

### 3. ADR-0035의 해당 절에 정정 표시를 붙인다 — 지우지 않는다

틀린 기록도 기록이다. 그 절이 어떻게 틀렸는지가 이 문서의 내용이고, 지우면 다음 사람이
같은 함정에 다시 빠진다. **인용하지 말라는 표시만 붙인다.**

## 무엇을 배웠나

**"같은 입력으로"를 확인하지 않고 "재현되지 않는다"고 적었다.** 재현성 주장은 입력을
고정했다는 증거가 있어야 성립하는데, 그 증거가 없는 채로 결론을 냈다. 그리고 그 결론이
*"기존 백테스트 결론 전체의 신뢰도가 흔들린다"*는 큰 주장이었다.

이 저장소에는 같은 종류의 반성이 이미 있다 — [ADR-0033](0033-unadjusted-splits-broke-mean-statistics.md)의
*"순위 통계가 멀쩡하다는 것이 데이터가 멀쩡하다는 뜻이 아니다"*. 이번 것은 그 짝이다:

> **두 결과가 다르다는 것이 계산이 불안정하다는 뜻은 아니다. 입력이 같았는지부터 본다.**

## 한계

1. **8/9 패널의 `raw/`를 복원하지 못해** 종목 집합이 절반씩 갈린 원인을 확정하지 못했다
2. 지문은 **파일 크기 기반**이라, 크기가 같은데 내용이 다른 갱신은 못 잡는다
3. 이 결정은 KR 패널로만 확인했다. `--market US` 경로는 같은 코드를 타지만 재보지 않았다
